# 第二轮协议：历史反例能否否决目标页一致性

此协议在第一轮 `final-r1/report.json` 已生成、第二轮实现／运行前写入。第一轮 36 个转移、216 次模拟请求的负结果保留，不回改原协议。它不是盲测或外部注册，而是根据第一轮失败开展的显式研发迭代。

## 要修正的具体失效

第一轮“锚点重新分配”中，单参数对照曾显示旧规则不适用于另一个栏目；但最终页中旧规则与旧锚点又一起指向推荐区，第一轮防护仅凭最终一致性放行。历史负证据没有进入否决条件。

第二轮候选：在第一轮防护之上，若本次改变了曾出现定位不一致的参数，则返回“历史反例要求重分析”。不自动把有限观测提升为一般因果依赖，也不把单参数探测没有发现问题写成独立性证明。

**完整强基线就是相同事实上的常规合取：证据齐备且目标页一致，且未触发历史反例。** 它应与平表候选、图编码候选逐项等价。不能只和上一轮双定位器比较后宣称新机制创新。

## 固定扩展

沿用全部 12 个原机制族，增加以下 2 个，每族仍用旧数值 10／42／73，共 42 个转移；每例仍 6 份真实执行器模拟响应，共 252 次模拟 HTTP。

13. **未曾观察到的共同失效**：单参数对照的旧规则都与锚点一致，最终页把旧 class 与旧 ID 一起转给推荐区。用于检查“历史反例否决”是否仍会漏放。
14. **可逆的参数效应**：校准栏目使旧 class 指向错误区，但最终另一个栏目又使旧 class 正确指向目标。用于检查保守否决是否拒绝本可正确复用的任务。

新反例在第二轮实施前确定，不因不利于候选而删除。不增加免费语义标签，不用真值创建锚点；保留原单参数控制值与最终目标值不同的设计。第二轮不调阈值、不自动修复选择器、不部署生产。

## 继续／停止规则

同时报告两轮不同证据集，不将增加机制族后的数字直接视作同分布效果提升。第二轮在同一 42 例上同时计算原防护、历史反例否决及完整合取基线，报告错误接受、安全拒用和页数成本。

如果候选与完整合取基线等价，定位为工程参考，不升级为新专利核心。如果共同失效仍导致误接受，明确当前问题是任务语义锚点不足，而不是缺少图结构。后续不得以更多同源定位器替代独立的任务目标证据。
