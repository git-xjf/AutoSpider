# AutoSpider 逐项专利对照与研发判断

核查日期：2026-10-07。代码范围为 `D:/VsCode/syslabe/AutoSpider`；用户指定的 `runtime/` 是运行产物目录，执行器、验证器及 MCP 服务的源码位于其上级目录。参考了用户提供的既往会话及本次实际代码。

## 1. 本轮结论

两种情况同时存在，但不能把“代码已经有区别”直接写成“专利创造性已经成立”。

已有的类型化 CrawlSpec/PageModel/CrawlPlan、确定性编译与执行、服务内 QA、紧凑工具回执、只在验证后复用记忆，具有具体工程内容，之前的概括没有讲清楚。这部分应补充实施例、接口与性能证据。可是，LLM/MCP、HTML 精简、列表与详情规则、试采后修复、多传输模式、模板记忆等方向都有较近公开，单独或简单串联主张的创新强度较低。

本轮发现原验证器的实际漏洞：少数详情模板保留能匹配但为空的旧正文占位，导致整类页面正文缺失，而全局空值率仍满足门限。原代码没有按路由结构独立检查必填字段。本轮已研发并验证“已观察路由结构 × 必填字段独立门禁”，输出实际失败页面对应的补证指令，并将失败阻断接入自动草稿的记忆提交流程。

这是已经落地的技术改进，适合作为窄范围候选交底。其专利创造性仍待证明：结构变体、空字段触发代表页补训练已有强先例，分组统计与预算常量存在直接组合动机。因此，当前更准确的判断是：**旧工程细节需要讲清楚，潜在核心仍需要进一步技术研发和对比证据；不能只靠文字包装完成创新。**

下文是技术研究对照，不是授权保证或自由实施（FTO）结论。授权权利要求的全部必要特征、公开说明书的技术启示、专利族地域与法律状态，应分别核对。

## 2. 判定规则

| 标记 | 含义 | 应采取的动作 |
|---|---|---|
| A：已有实质实施差异 | 代码存在具体处理或控制关系，区别可定位 | 写明输入、处理、输出、异常与实验；继续核查创造性 |
| B：常规组合风险高 | 区别主要是工具、接口、角色、参数或已知模块排列 | 用作系统背景或从属特征，继续研发真实失效问题 |
| C：已新增候选机制 | 本次实现并验证，但尚无充分专利性证据 | 保留窄技术交底，做消融与近似技术组合检索 |
| D：尚未实现 | 只有设想、提示约束或路线图 | 明确写待研发，不能冒充完成实施例 |

“未在本轮文献中发现完全相同链条”只支持继续研究，不等于新颖性或创造性已确立。不同专利不是直接拼在一起做新颖性判定；组合启示主要影响创造性分析。

## 3. 逐项专利表

各表均为对公开文本的概括，没有逐字搬用其权利要求。B 为授权文本、A 为申请公开文本；对保护范围优先核对授权文本，对技术公开同时参考说明书与公开版本。

### P1：LLM 与 MCP 自动爬虫

来源：[CN120910335B](https://patents.google.com/patent/CN120910335B/zh)，授权公布 2026-05-15；较早公开版本为 [CN120910335A](https://patents.google.com/patent/CN120910335A/zh)。

| 授权权 1 要素组 | 项目对应 | 剩余区别与判断 |
|---|---|---|
| 自然语言需求标准化；MCP 浏览器加载、动态捕获与完整 DOM | Lead、MCP inspector、CrawlSpec | 流程相近；日常采用紧凑证据及服务端构造模型。A/B：有工程区别，HTML 精简已有其他公开 |
| DOM 定位；OCR 与 DOM 交叉验证；接口语义匹配；LLM 还原鉴权 JS | DOM/网络探针、HTTP/API/浏览器模式 | 未发现本项目强制实施 OCR 交叉验证与鉴权 JS 还原链；不能因主干相似断言满足授权权 1 全部特征 |
| 模板脚本、语法/灰度/完整性测试、规则和 LLM 两级修复 | 类型化 IR、确定性执行、样本 QA、RepairPatch | 字符串脚本与受限 IR 有实施差异；试采修复本身为 B。分层空值门禁为本次新增 C |
| 预处理和存储 | 输出文件、site memory | 通用工程机制，B |

动作：交底重点写受限 IR 与验证控制关系；将“MCP 自动生成爬虫”作为背景。授权版已加入更具体的多模态、接口与鉴权限定，不能沿用只看申请摘要的宽泛判断。

## 5. 需要追加的研发证据

本轮本地执行实验已经证实少数空正文被全局均值掩盖，且新门禁可以阻断。它尚未证明真实站点的泛化、模型修复成功率、token 降幅，或相对于现有自适应代表页方法的非显而易见效果。

下一阶段应围绕同一个问题形成可执行闭环：登记候选页面与未观察分层；在路由与实测结构不一致时按字段缺口触发拆分；将缺口绑定实际失败证据；由服务端执行与消费补取预算；将修复版本、受影响分层及复验结果绑定；最后要求完整验证依据才允许提交记忆。每项独立看仍可能常规，价值要由相互控制产生的效果证明。
