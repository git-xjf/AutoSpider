## 2. 工程改动与版本证据

[采集器](../../../scripts/capture_public_memory_pages.py)仅在缺少 MIME 时，要求严格声明／BOM 编码解码及有界 HTML 文档签名，才允许归档。明确的非 HTML MIME 不会被覆盖；响应头保留原样，不补造 Content-Type，不赋予脚本执行许可。编码声明读取真实 head 标签，排除注释、script、style、template、noscript、title 中的伪声明，以及 body 内的 meta；坏编码继续拒绝。

当前源码是采样后的进一步加固版本，不能冒充采样当时执行的源码。三个成功采样报告记录的版本均为：

- [离线审计脚本](../../../scripts/audit_cls_source_documents.py)：SHA256 `56bbb9b4047728244aa345b5feb1037d55d717965b0464c614b8cc5c70fec0be`。

两详情的 `body_redacted=true` 是真实保存状态。现有脱敏器也会规范化公开 URL，因此该状态不证明发现了凭证；同样，文件中没有 `[REDACTED]` 也不证明原字节未变。缺少原始字节时，不断言具体字段完全保持原样。

## 3. 实际证据与不能推出的结论

| 已观察到 | 支持的结论 | 不支持的结论 |
| --- | --- | --- |
| 3 份已保存 HTML，哈希与各报告一致 | 这些保存版本可核对、可解析 | 3 份完整动态回放包 |
| 两详情为 singleton `articleDetail`，URL／query／id 相同 | 保存版本存在明确实体标识关系 | 独立实体真值或自动来源发现已完成 |
| 短讯正文 228 码点，仅在内联数据找到完整值 | 静态正文选择器不能覆盖这份保存输入 | 实际浏览器不会显示正文 |
| 长文内联 HTML 3072 码点，归一文本 2590 码点，与两个嵌套 SSR 节点相同 | 同响应双表示一致，选择器粒度仍有歧义 | 两个独立来源确认、唯一正确选择器 |
| 0 个浏览器资源闭包、0 份独立语义参考 | 真实回放和语义效果尚不能评价 | 新机制胜过现有方法，或真实站误绑定率为零 |

冻结 v3 依赖整响应 JSON、记录数组、纯文本字段及完整资源；当前是 HTML 内嵌单对象，长文还有 HTML→text 变换。因此这是输入合同不适配，不是 v3 在真实站上的准确率失败。不能人工制造 `source.json`、重写页面 renderer 后声称原站回放成功。

## 5. 对一件专利的研发决策

论文／专利／官方文档核验进一步排除了“JSON＋SSR 一致性”“普通变异回放”“增加路径 guard”等宽泛创新包装。[逐项边界及出处](RESEARCH_BOUNDARY.md)

当前主问题限定为干预可采纳性：干预改变了正常消费路径，还是诱发了不一致后的恢复路径？这尚是待证假设，并无获胜机制。研究产出必须是一个具体可执行判据，而不是多加一个 agent 或一个 `valid` 字段。

后续实验预先设置以下门槛：

1. 先补齐获准、可核对的实际运行资源；未补齐不出原站效果数字。
2. 对照至少包含静态匹配、完整正负差分，以及具有相同阶段／恢复观测的强基线；使用相同公开输入、候选、资源和预算。不靠省略强基线的必要检查获胜。
3. 同时报误接受、覆盖／拒判、真实加载／观测开销；与强基线比较同覆盖下的误接受，或同误接受约束下的覆盖与成本。不能把全部 `PENDING` 称为成功。
4. 正常 hydrate、合法客户端更新、恢复／重建、缺依赖和非确定性分别统计；受控故障注入与自然故障不混计，同一网页重复轮不当独立样本。
5. 若具体机制与强基线等价，停止提升交底；只有实质区别、可重复技术效果和失效边界成立后，再更新专利要件表。

目前可交付的是有真实输入支撑的研发问题和证据缺口，不是可直接提交的专利申请稿。下一步需要另外明确完整浏览器资源采集的范围，或取得用户提供的脱敏资源包；本轮没有推定扩大采样授权。
