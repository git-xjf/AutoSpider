# 真实 HTML 输入下的 SSR／hydration 研究边界

> 后续事实更新：新增两份与旧原始哈希匹配的原字节 HTML，正文／内嵌 JSON 未改变；CDN robots 403 阻止脚本采集，未启动原站浏览器。见[资源回执](RESOURCE_CAPTURE.md)。本文“详情原始字节未保存”是核查时的历史状态；“缺完整运行资源、未观察原站 hydration 路径”的边界仍成立。

核查日期：2026-10-21。用途：为一件专利的后续研发划定证据边界；不是论文贡献包装，也不是可申请、可授权或不侵权结论。本轮只查文献与框架官方说明，没有再次访问新闻站、补抓脚本、运行原站浏览器或改动生产代码。

## 1. 先给结论

“JSON 与 SSR 一致”不能成为新增创新点，也不能成为两票独立确认。只修改内嵌 JSON 而保留 SSR，可能制造初始表示不一致，使后续 DOM 差异来自 hydration 恢复或另一渲染路径；即便这种差异确实由干预引起，也不能据此证明原样页面的正常路径如何消费该字段。

既有方法已经公开变异破坏前置条件、重复基线控制不确定性、执行追踪及变换检查。因此，增加“路径检查”“hydration guard”“失败则 unknown”等宽泛要件，不能直接当作实质创新。现有公开并不等于已解决当前所有实现问题，但剩余问题要用具体机制与强对照检验，不能只改术语。

## 2. 本次真实输入不是冻结 v3 的实验对象

依据本地 [SOURCE_AUDIT.md](SOURCE_AUDIT.md) 已完成的离线结构审计，而非本轮重新访问网页：

- 两份详情是脱敏保存的 HTML；`script#__NEXT_DATA__` 中 `/props/pageProps/articleDetail` 是单对象，不是整响应 JSON 中的 records 数组。
- 短讯 `content` 为 228 码点纯文本，静态保存文档未找到相等正文节点；这不说明浏览器运行后不存在正文。
- 长文 `content` 是 3072 码点 HTML 字符串，抽取后为 2590 码点文本，与 SSR 正文相等；外层、内层两个节点同时相等，不能据此唯一确定 selector。
- 完整浏览器资源 capsule 为 0，独立语义参考为 0。脚本引用不等于已取得脚本；详情原始响应字节未保存，不能称为原站字节完整复现。

因此，目前只能做保存版本的解析及表示一致性审计。不得把 singleton 包装成数组、制造 `source.json`、改写页面 fetch 或注入自写 renderer，再报告为原站回放成功。`__NEXT_DATA__` 的存在也不足以确定原站 React 版本、调用 API 或具体 hydration 行为。

## 4. 四类结果必须分开

| 观察 | 当前最多可解释为 | 不应声称 |
| --- | --- | --- |
| 静态 JSON 文本与 SSR 文本相等 | 同一保存响应内的表示一致 | 两个独立来源确认、真实语义正确、运行时读取绑定 |
| 单边改 JSON 后 DOM 出现 canary，但发生 mismatch／重建 | 在该干预执行中存在响应，可能经过恢复路径 | 原样 hydration 的正常取值路径已证明 |
| 单边改 JSON 后 DOM 不变 | 该次可观察输出未响应 | JSON 没被读取、所有路径无依赖、站点错误 |
| 同时改 JSON 与 SSR 后页面稳定且有 canary | 双表示同步修改后的存活／一致性对照 | JSON 导致原 SSR 节点变化的独立因果证据 |

DOM 的初始值已由 HTML 提供；若同时修改它，等于直接改了待观察输出的一种输入表示。后续看见标记本身无法区分“浏览器沿用 SSR”“客户端重新生成”“恢复后覆盖”等路径。这是当前实验解释的限制，不是声称所有同步干预都没有研究价值。

## 5. 后续实验的最低有效性要求（尚未实施）

先取得另外授权、范围明确且资源完整的离线 capsule；失败、缺失脚本或原始输入不可核对时保持 `PENDING`。本轮不以研究需要推定采集授权。

只有具备真实运行资源后，才可在独立研究版本中定义 inline-source lens，绑定唯一入口响应、script、entity、JSON pointer 及 HTML-content→text 合同。合同适配本身是工程需求，不自动成为创新。正文、title、brief 的对照是同一对象的不同字段，不能冒充 foreign-entity 对照。

实验至少区分原样两次、仅改 JSON、仅改 SSR、实际其他字段负对照，以及可选的双表示同步存活对照。每次固定环境与实际资源，对观测时间点、节点身份、异常和重新渲染保留轨迹。不能只比较最终 `textContent`。

“路径可比”需操作化，而非只加一个布尔字段：

1. 说明目标是初始 HTML 解析、原样 hydration、hydration 后正常更新，还是错误恢复；它们不是一个证明对象。
2. 列出本实验能观测的恢复／替换／异常边界和观测盲区；无法安装真实版本对应的观测时标 unknown。不得为通过测试改写框架行为。
3. 记录 source 实际消费、目标 sink 到达、候选节点替换及相关阶段；脚本 hash、HTTP hash、`networkidle` 或控制台未报警均不能单独证明这些事实。
4. 若只证明某个边界未被观察到，不写成完整路径等价。需要严格等价时，应明确比较哪些 trace／guard，并说明漏观测和并发调度的影响。
5. 不强行要求所有指令路径逐项相同：输入依赖分支可能就是待观察作用。必须先界定要排除的是恢复／异常路径，还是任何控制依赖；否则严格 guard 会把有效依赖也排除。

这些是可信实验的约束，不是确认新颖的权项骨架。若强 baseline 使用相同真实输入、同阶段划分、同守卫、同预算后得到相同结论，新增能力就只是适配和证据修复。

## 6. 暂留两个 research hypotheses，不提升为专利结论

**H1：干预可采纳性。** 是否存在可执行且低成本的判据，区分“原样消费路径上的字段响应”和“单边双表示冲突诱发的恢复响应”？先与同样具备 trace／恢复观测的常规差分 baseline 比较；仅有不匹配检测、无错误日志或守卫标签不足以构成区别。

**H2：受限观测下的证据分级。** 在拿不到完整内部路径、但能观察真实框架阶段及节点生命周期的情况下，能否给出可复核的证据等级和必要拒判条件，避免把正常更新、恢复重建、SSR 直接标记混为一类？要测误接受率与覆盖率的共同变化；如果全部拒判才安全，或与同约束 baseline 等价，就没有证据支持新增技术优势。该问题仍可能只是既有程序分析与工程测试的组合。

不将“JSON＋SSR 双表示一致性”“路径 guard”“阶段收据”“pending 状态”单独推荐为创新点。下一步只应在上述假设中选择具体可执行机制并做否证实验；不能从这两份静态文档直接补成专利效果。
