# 一件专利的研发决策：不再扩大已知机制的表述

> 2026-10-21 后续决策：核验授权已取得并执行，现有 3 份保存页面，但资源闭包和独立语义参考仍为 0。真实输入将问题收窄到 SSR／内联状态共存下的干预可采纳性；普通一致性／路径 guard 仍不足以成为新增创新。最新[研究边界](../memory-live-2026-10-21/RESEARCH_BOUNDARY.md)与[继续门槛](../memory-live-2026-10-21/RESULTS.md)适用；下文保留 10-20 的决策记录。

日期：2026-10-20。本文是阶段性研发决策，不是已完成的专利申请书。

## 当前已排除的“创新包装”

v2显示完整依赖缓存可以等效实现当前作用域复用。v3窄检索又确认，来源复制折扣、支持撤回、按来源挑证据，以及源值变异后的输出检查均已有直接先例。它们可以用于工程方案，但不能仅改称“智能体长期记忆”或增加角色分工就作为新增技术核心。

特别是 [CN111954880B](https://patents.google.com/patent/CN111954880B/zh) 的权5已写源值变异与汇值影响；该从属项包含权1的执行追踪等限定，不能反过来说任何差分回放都必然侵权。新颖/创造性检索与实施自由分析是不同任务，现阶段没有作侵权结论。准确对照在 [PRIOR_ART.md](PRIOR_ART.md)。

## 唯一继续保留的具体研究问题

在同一网页同时渲染目标记录、推荐项、镜像字段或旧版本时，怎样从公开任务和实际执行证据建立 `record–field–candidate` 绑定；在候选值相同、干预改变分支或多个区域共同响应时，何时必须拒判？

本轮参考实现将其中一个前提**显式作为任务输入**：哪个响应、哪个实体键、哪个字段是目标来源。它没有自动发现这个前提。如果实际任务只说“采集正文”，却没有公开API字段合同，就不能从评分标签免费获得Binding，再宣称自动找到正文。

因此值得继续验证的缺口是任务到来源绑定的取得与可执行判别，而非再为收据增加字段。这个问题目前不被认定为新颖：自动字段映射、wrapper归纳和信息流分析也必须纳入后续窄检索。

## 下一个实现应由真实失败约束驱动

需要允许取得的完整输入和失败定义，至少覆盖：

1. 任务公开可见的目标URL、字段要求、列表关系或其他来源约束，不使用正文标签代替。
2. 原始HTML、关键脚本、API响应、请求方法与可脱敏的请求参数；缺少的资源明确标记，不补造。
3. 人工核对的目标实体/字段/区域及失败原因；另标“字段绑定正确但上游内容错误”。
4. 至少一个发生实际失败的页面和一个未失败的保护页面；若比较记忆更新，需有可核对的前后版本，不用不同文章冒充自然版本变化。

当前运行目录没有保存这种完整输入。静态外部语料可验证正文抽取边界，但不能补出API、脚本与天然版本序列；见 [DATA_AUDIT.md](DATA_AUDIT.md)。本轮受控浏览器实验只用于确认判据能否执行以及哪些反例仍无法处理。

## 继续/停止判据

与相同公开信息、相同资源、相同实际回放预算的完整差分基线比较。只赢字符串一致或省略负对照的方法，不足以继续主张新机制。只在人工提供正确Binding后成功，也不能证明任务到来源发现有效。

如果新实现形成相同的干预矩阵和决定，就将其定位为参考验证器，不继续改名出v4。只有出现具体机制差别，且解释它解决了哪类既有方法失效、有何新增费用与失效条件，再重做专利区别表和交底。无需承诺必胜，也不能把未证明的差异写入权利要求。

## 申请材料的当前处置

保留v1/v2负结果和既有交底，不将本轮参考实现升级为“已完成创新”。当前可以交给代理师的是需求、既有能力、近似公开、实验及不支持的命题；还不应提交宽泛的“多智能体记忆系统”发明申请来代替技术问题的解决。

下一步最有价值的输入是一个允许采集的目标公开URL，或去除Cookie/Authorization等凭证的HTML+HAR及任务说明。不能为了补证而读取私有会话、绕过登录/访问限制或把抽取结果冒充输入快照。

用户后续已选项目已有公开新闻站，目前具体到财联社。现场核查发现Next.js内联articleDetail及实际公开脚本，但当前项目strict DNS检查因Fake-IP阻断。已保留[现场审计](LIVE_CAPTURE_AUDIT.md)与[预检回执](../../../runtime/experiments/patent-memory-v3-20261020/live-cls-20261020-preflight/report.json)，不把网络可达性检查升级成真实网页回放证据。尚未得到单次进程公共DNS验证模式授权时，不改配置、不继续受阻采集。
