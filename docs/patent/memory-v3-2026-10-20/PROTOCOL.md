# v3：字段来源差分回放可行性协议

日期：2026-10-20。来源：v2中“公开元数据自洽但正文错误”的反例。本轮不是再造一个缓存算法，也不预设找到可申请专利。

## 1. 精确问题及研究停止线

没有Article来源标记时，抽取候选与API字段的文本一致可能只是偶然：两个记录恰好具有相同文本，或推荐区复制了另一个记录。能否通过真实浏览器中的受控响应干预，区分“值碰巧一样”和“候选在此上下文中响应目标字段”？

目标是任务明确指定的实体/字段来源绑定，不是判断发布者提供的文章事实真假。若目标API字段本身错误，本方法不应被描述为恢复了真值。任务必须公开指定response、实体键和值字段，不能用评分标签倒推来源。若项目实际没有这种任务输入，就不能免费假设已经知道哪个JSON字段是正文。

检索已命中MUTAFLOW(ASE2017)、Privacy Oracle(CCS2008)、DOM Invader(2021)等差分/标记传播先例，因此“替换输入→重放→看输出变化”不是本轮可直接主张的创新。本轮实现定位是可审计的参考验证器，以便决定该路线是否值得进一步研发；不能把常规方法重实现写成新算法。

## 2. 输入、执行与严格合同

`Bundle`包含入口HTML、脚本和JSON等完整响应资源、完成条件及相同候选CSS集合。资源按URL、method、请求体匹配；没有录入的请求一律阻断。每次回放使用新的浏览器上下文，service worker阻断；不向真实网站修改数据，不绕过鉴权。

`Binding`包含response地址、records JSON pointer、entity键和值、目标字段。源字段只支持纯文本输出合同：规范化空白后，基线候选文本等于源字段值。一般HTML渲染、截断、翻译或其他变换不满足该合同，可返回未知，不能假装支持任意正文转换。

最少执行：两次原样回放检查稳定性；一次仅替换目标字段的唯一canary；对记录集合中的每个非目标记录分别替换对应字段作negative control。所有候选共享每次真实浏览器执行。要求唯一非空候选、基线对应、目标canary对应、负对照不改变该候选，及同一可比较的结构路径。多候选同时通过时不自动确定哪个是正文。

有限negative control仅覆盖已声明记录与这些替换值，不证明对任意输入独立或所有分支安全。字段变更可改变程序分支；新快照不能复用旧快照收据来授权未测分支。

## 3. 记忆与公平对照

收据绑定完整资源内容、Binding、候选库、协议实现版本和浏览器版本，保存真实回放轨迹与哈希。只有完全相同上下文可以命中缓存。SQLite仅由研究代码创建；不读取/改写生产记忆库。精确缓存是常规memoization，不是本轮创新点。

至少展示同一公开输入的文本一致基线、target-only差分消融、完整成对差分验证。文本一致可以利用公开源字段；不允许将正确正文标签仅提供给新方法。完整差分对照属于直接先例方法族的工程实例，不得声称复现了MUTAFLOW原系统或击败完整动态taint。

消融可以离线从相同完整轨迹中判断对应条件，但这种计算不代表消融实际发生了更少浏览器执行；若没有单独执行，必须明确共享观察的费用。缓存命中节省的是已下载资源上的浏览器回放，不是HTTP下载或模型调用。

## 4. 冻结与指标

独立生成的小型受控浏览器页面在调用引擎前冻结为manifest，并记录payload/source哈希。保留无schema、不同实体相同文本、混合区域、多角色复制、canary触发分支、截断、缺失/重复实体、503、缺资源、新快照分支和上游语义错误等反例。开发者可见生成器，因此不称外部盲测或真实新闻站效果。

预算按实际浏览器page load计算，包含两次基线；不足保持待证明。记录每次匹配、文本、结构路径、请求履行/阻断、JS异常、实际page load、浏览器启动和耗时。输出有效/待证明、选中的规则、候选集、缓存命中及未覆盖原因。

评分区分来源绑定、精确字段输出、语义真值和拒用；上游语义错误不能因字段绑定成功而计成“正文恢复成功”。同文本不同实体的价值是消除错误来源归属，不应虚构为输出正文字符串发生了改善。

## 5. 证据门槛

本轮若只显示成对差分优于文本一致或target-only，可以支持协议中负对照/基线检查的工程必要性，不能独立支持创造性。相对同信息完整差分没有独立机制或额外效果时，应停止将其包装为专利核心。

真实动态网页验证需要允许使用的完整HTML/JS/响应和任务Binding，另需人工核对的来源及正文标注。现有静态语料和抽取结果不能补造这些资源。具体数据缺口见 [DATA_AUDIT.md](DATA_AUDIT.md)。
