# 第二版验证协议与声明边界

日期：2026-10-19。目标是验证上一轮发现的错误泛化能否修复，并判断修复是否超出常规缓存与代表页审核。不是预设正结果的专利包装。

## 1. 固定研究问题

当同一路由出现非空错误正文、少数模板变体或短暂访问故障时，怎样使字段抽取规则的历史记忆只在有证据支持的范围内复用，而不把访问失败、证据不足和规则反例混为一谈？在相同可见信息和页级审核预算下，该机制相对完整依赖缓存还能否产生额外效果？

本轮实现固定字段 `content`、固定候选 CSS 库、固定来源合同。它不训练模型，不让模型生成新选择器，不修改生产系统。研究范围不是通用智能体记忆或多智能体协商。

## 2. 事先冻结的数据与后续代码修复

24个确定性场景：9个开发场景、15个单独生成的工程留出场景。固定种子 `20261019`。每场景含历史任务和重复/恢复/版本变化序列；另有无历史收据的冷启动场景。

数据在首次调用策略评价前冻结至 `runtime/experiments/patent-memory-v2-20261019/fixtures-manifest.json`：

- payload SHA-256：`b2000fe14109e3d8cd0c3070ce3d9281be4a1d8da58f8b937d3b5f451ac1b2e7`。
- 冻结时 fixture 源码 SHA-256：`a343bd9b91782535115c67b5a1a58ec6808b6ea4dfa36139eda2bb303c5ecc60`。

本协议在数据冻结后、首次结果汇总前写入，不是第三方预注册。工程留出不是外部盲测：开发者知道变化族；不据此推断真实网站总体性能。通用实现缺陷可以修复，但须重跑并记录源码哈希，不得依据留出评分修改选择策略、候选库、标签或删掉负结果。

## 3. 公共输入和固定合同

所有策略取得同一批已下载的 HTML 快照、URL、列表标题、HTTP状态、执行模式、合同与候选版本。策略API不接收真实正文或期望选择器。只有评分阶段读取 `scoring_expected_text`。

合同要求候选：CSS有效且唯一非空；存在唯一受支持 schema.org Article/NewsArticle 祖先；候选声明 `articleBody`；该 Article 的唯一 headline 与列表标题对应；唯一来源 URL 与目标 URL 对应。缺失或歧义保留待审核；明确不匹配或无候选判为该范围无效。临时503、429等只改变访问通道，不写成选择器反例。

投影存储全部上述合同输入的关系结果，而非正文语义真值。标题比较、URL比较、节点筛选已经在生成投影时计算，必须计费。`VALID` 仅表示合同通过，不证明网站标记真实。专设“元数据自洽但正文错误”场景检验这一限制，不从正文正确率分母删除它。

## 4. 对照与预算

每轮页级追加审核预算分别为 `0 / 1 / 2 / 4 / 10`。一次页级审核评估同一候选库；未覆盖的无证据范围保持待审核。温启动审核成本与评估成本分列；同一场景/预算/策略使用独立SQLite，序列内共享自己的收据，不跨实验串库。

| 策略 | 用途 |
|---|---|
| always_reuse | 不审核、直接复用旧规则的弱对照 |
| prefix_contract_checks | 前缀审核与过度推广对照 |
| structural_representatives | 结构变体代表页对照；非文本相似不等于来源相同 |
| exact_url_receipts | 绑定URL与完整快照的保守基线 |
| complete_projection_fifo | 同合同、同完整投影、顺序处理的缓存基线 |
| complete_projection_greedy | 同合同、同完整投影、同未覆盖范围增益排序的强基线 |
| counterexample_scoped | 本轮候选；同证据等价类收据、三态、版本和访问隔离 |

强基线与候选使用相同安全状态、输入和排序。两者在当前固定合同下走相同逻辑，等效是预期结果，不能把它解释为独立方法的性能胜出。FIFO对照只能分离排序贡献，不能单独证明创造性。

## 5. 指标与费用

逐页报告正文真值正确、误复用、拒用、临时不可访问，以及合同通过/不合规和“合同通过但正文错误”。拒用不能计成正确提取；仅有一部分放行时同时给出正确覆盖与误放行，不能只报告已接受页面精度。

记录实际审核次数、审核页、缓存命中、SQLite收据和状态；另列公共HTML解析次数、候选观测次数、快照字节、投影耗时和策略耗时。耗时只反映该机器的单次离线执行，不作统计显著性或生产加速结论。生成投影后的审核函数很轻，少调用该函数不必然减少总工作量。

没有真实HTTP或模型调用，因此不报告请求、token、推理成本节省。没有真实网站数据，因此不报告线上自愈成功率。

## 6. 结论规则

优于直接复用或前缀审核，最多支持修复已有可靠性缺口。若候选与完整投影+同排序缓存相同，则本轮未证明额外技术效果；不得把状态名、收据名、哈希或多智能体角色当作新颖性依据。

若合同自洽但正文错的页面仍被接受，应明确认定来源合同的语义能力不足，而非删掉该页或把其算成语义正确。本轮不得据此宣称已经完成可直接申请的发明。

## 7. 可重复性与后续门槛

保留冻结数据、结果JSON、源码哈希、命令和测试记录；旧版文件不覆盖。下一轮如研究新的语义见证机制，须重新检索、重新冻结未使用数据，并与取得同等观测的强方法对照。是否申请仍需逐项权利要求评估；实验优胜不自动等于满足授权条件。
