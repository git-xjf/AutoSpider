# 分层验证与补证机制：实验结果和下一阶段协议

日期：2026-10-07。结果文件：[results.json](../../runtime/experiments/patent-coverage-20261007/results.json)。本轮实际完成的是确定性机制回归与本地真实 HTTP 执行链，未运行公网模型修复或虚构 token 指标。

## 1. 已完成实验 E0：均值掩盖与采样盲区

运行：

```powershell
D:\conda_envs\mytorch\python.exe scripts\benchmark_verification_coverage.py
```

固定十条记录、三个必填字段，空正文记录有单独 `/special/` 路由。对照复现旧全局门禁：空字段阈值、全局完整性、语义和重复检查；实验组在相同记录上追加独立分层检查。样本量为五，prefix 为 `[0,1,2,3,4]`，boundary_spread 为 `[0,2,5,7,9]`。

| 情形 | 旧门禁：prefix / 分散 / full | 新门禁：prefix / 分散 / full |
|---|---|---|
| 尾部两条变体，8/9 | PASS / PASS / PASS | PASS / FAIL / FAIL |
| 中部两条变体，4/5 | PASS / PASS / PASS | FAIL / FAIL / FAIL |
| 未取样单条变体，8 | PASS / PASS / PASS | PASS / PASS / FAIL |

对长度二的九个连续位置窗口，前缀样本与其中五个有交集，分散样本与其中八个有交集。这是固定布局上的覆盖计数，不能解释为随机站点的检出率或统计显著性。单条未采样例明确显示任何该取样方案都可能遗漏，full 才发现问题。

## 2. 已完成实验 E1：本地真实执行器与记忆门禁

运行：

```powershell
D:\conda_envs\mytorch\python.exe -m pytest tests\e2e\test_coverage_gate.py -s
```

本地 HTTP 网站返回十条链接和十份详情 HTML。两份变体保留空 `.content` 节点，正文位于 `.alternate`。测试通过原生 `http_html` 执行器及自动草稿流程执行，不伪造爬取结果。每个情形使用独立临时任务、草稿及记忆目录。

| 策略与规则 | 终止阶段 | 旧门禁 | 新门禁 | 列表/详情 HTTP 请求 | 记忆 |
|---|---|---|---|---|---|
| prefix，错误 `.content` | full，10条 | PASS | FAIL | 2 / 15 | 不提交 |
| boundary_spread，错误 `.content` | sample，5条 | PASS | FAIL | 1 / 5 | 不提交 |
| prefix，修复 `.content, .alternate` | full，10条 | PASS | PASS | 2 / 15 | 提交 |
| boundary_spread，修复 `.content, .alternate` | full，10条 | PASS | PASS | 2 / 15 | 提交 |

错误任务全局必填空值率为 6.67%，失败路由正文空值率为 100%。旧门禁 PASS 是对本次实际采集记录应用原门限的对照判断；没有另行运行一份旧版本程序。修复规则在受控站点中由测试指定，没有模型自主修复成功率指标。

补证请求只包含 `content` 与 `/special/` 的实际失败 URL，无文章正文。该实验验证定向指令和记忆阻断，未执行自动补证预算接口。

## 3. 已完成实验 E1b：边界和回执回归

单元验证覆盖：路由标识归一化；查询值只从签名移除而抓取 URL 保留；代表页优先选择实际失败行；合并和分离的多字段失败；证书只声明已观察范围；多达三百分层时 QA 回执仍不超过 16,000 UTF-8 字节；裁剪保留全部失败计数；矛盾 PASS/失败证书不能提交记忆。

HTTP 与 Playwright 既有回归验证取样行为、原 prefix 兼容及满量行为。全量项目测试为 **500 passed，1 warning，39.98 秒**。第三方 Pydantic `lifespan` 前向引用警告与本轮分层门禁无关。结果 JSON 记录执行命令及关键源文件 SHA-256，便于对应本轮实现。

## 4. 下一阶段 E2：真实页面配对任务

选取 6–10 个允许采集的站点/公开数据集，优先选择实际存在异质详情页面的集合，而不只选成功的标准新闻页。每站至少两个任务；保留取得日期、页面快照哈希、最终 URL、字段合同及人工标注，区分真实缺失字段和抽取失败。当前没有预选站点及新的真实站点结果。

模型、模型版本、提示词、字段合同、候选集合、请求及模型输入预算固定，按相同任务对照：旧 prefix+global、分散+global、prefix+stratum、分散+stratum。为验证专利候选的额外作用，还需实现接近现有公开的结构变体代表页反馈基线，不能只与最弱前五条方案比较。

主指标为最终误放行：存在人工确认的系统性必填字段抽取失败，却给出 final PASS 或提交记忆。次指标为失败分层召回、真实无字段造成的误报、修复后正确率、成功分层回归率、附加 HTTP 请求、补证字节、模型输入 tokens、修复轮次和耗时。

模型 tokens 从真实调用日志记录，字符数仅为旁路诊断，不换算成虚构 tokens。成本应包含新增的验证和额外补证，缓存与未缓存输入分别保留。超过预算计为终止失败，不从分母移除。

## 5. 下一阶段 E3：消融与反例

| 消融/反例 | 要解决的解释问题 |
|---|---|
| 保持抽样，删除独立字段对门禁 | 效果是否只是更容易采到尾部页面 |
| 保持门禁，补证页面改为层内首两条 | 实际失败 URL 选择是否减少无效补证 |
| 相同补证请求预算，整页输入对比字段切片 | 受限输入是否在保持正确率时降低输入量 |
| 路由相同但模板不同 | 路由误合并是否使漏洞重现 |
| 路由不同但模板相同 | 误拆分是否导致小样本误报与成本膨胀 |
| 空字段真正不在网页中、正文为非空错误栏目 | 空值门禁不能处理的问题与语义边界 |
| 全量超过 1000 条、失败只在后缀 | 验证范围标记是否可靠阻止完整性声明和记忆提交 |
| 修复 minority selector 却破坏 majority | 版本绑定复验及回归门禁是否提供额外效果 |

前两项部分逻辑已由单元/E2E验证；其余不能视为本轮已获得结果。尤其同路由异模板是当前版本的已知局限，应作为研发首要失败样本。

## 6. 统计与研发决策

本轮确定性回归无需 p 值。未来真实任务按站点配对，报告原始任务数与所有失败；二元误放行用配对差异及适合样本量的精确检验，连续成本用站点聚类的 bootstrap 置信区间。不要把同站大量记录当作独立站点重复。模型多次运行先在任务内汇总，再做站点级比较。

研发验收阈值应在运行前登记，例如“同等预算下，新增机制无已知系统性失效的误提交；定向证据减少无关补取且不降低修复正确率”。数值目标由初始真实任务基线决定，不根据结果倒填。

判断规则：如果仅体现全局检查换成分组检查的预期效果，保留为工程改进并继续研发；如果可执行预算、证据绑定及复验控制在同等成本下产生可复现的额外效果，再扩展近似组合检索并凝练窄权利要求。实验能够支持技术效果，不能单独证明创造性。
