## 先按你的项目确定阅读范围

当前项目不是简单“三个智能体轮流聊天”，而是以下组合：

- `crawler-lead` 统筹，复杂新站才调用 `web-analyst`，失败后才调用 `qa-repair`；不是每次都启动全部角色。
- 紧凑探针提供证据，服务端构建 `CrawlSpec / PageModel / CrawlPlan`，固定执行器执行；不是常规任务都让模型生成任意爬虫代码。
- HTTP API／HTML／Playwright 路径、列表详情与分页、sample → QA → full → QA → memory。
- 站点工作流与选择器的 SQLite 记忆，兼容请求复用，失败重分析与受限补丁。
- 紧凑上下文、工具预绑定／按需发现、输出摘要和权限／网络边界。

因此下面同时覆盖网页规则、编排、执行上下文、过程记忆、知识图谱与验证。**生产记忆目前不是图数据库＋向量数据库；研究中的图编码也没有部署为生产机制。** 项目依据为[根说明](../../../README.md)、[复用服务](../../../services/easyspider_mcp/server.py)、[记忆仓库](../../../packages/site_memory/repository.py)及[验证器](../../../packages/validator/report.py)。

## 建议的阅读顺序

先读 **R01 → R05 → R06 → R09 → R10 → R14**，分别对应采集主链、MCP 协同、执行上下文、过程记忆、复用控制、预算与验证闭环。

如果主要想做“记忆＋知识图谱”，再优先读 **R11**；想研究写入延迟／记忆维护成本读 **R12**；想研究上下文选择与记忆遗漏读 **R13**。这些是阅读主题，不是已经证明可申请的创新方向。

逐件笔记标出了独立／从属权项、项目相似点和阅读问题。先弄清其输入、控制条件、失败处理及全部必要限定，再考虑自己的实质技术差别；不要只比较题名，也不要把不同角色名、数据库或应用场景直接算成创新。
