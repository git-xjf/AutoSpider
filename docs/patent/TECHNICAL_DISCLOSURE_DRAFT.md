# 技术交底草案：异质网页采集的分层字段验证与定向补证指令

版本：2026-10-07 / 研究候选稿。本文明确区分本轮已经实施的处理与尚待研发的闭环。它可供代理师继续检索与讨论，不是可直接提交的定稿。

## 1. 技术问题及触发条件

同一采集任务可包含多个详情路由或模板。已有规则在大多数页面正确，而少数页面仍保留旧结构中的空正文占位。选择器成功匹配该占位，执行器没有异常，但正文为空。若验证只汇总全部记录，少数页面的整列失效会被允许的空值率掩盖；前缀试采还可能完全未访问该类页面。

必须区分两种故障：必填选择器完全无匹配时，当前原生执行器已有异常阻断；本交底针对匹配但提取为空，以及由已观察的少数路由失效造成的误放行。

复现例：列表十条，八条 `/news/{n}.html` 使用 `.content`，两条 `/special/{n}.html` 正文位于 `.alternate`，但仍有空 `.content`。错误规则抽取 `url/title/content` 三个必填字段。全局空单元格率为 `2/(10×3)=6.67%`，正文单字段空值率为 `2/10=20%`，恰好满足原有门限。少数路由正文空值率为 `2/2=100%`。

## 2. 已实施方法

S1：接收采集字段合同及实际返回的记录集合 R。字段合同指明必填字段和列表/详情/单页作用域。保留执行器已有语义、重复率及全局完整性检查。

S2：选择 URL 字段，按 hostname、路径段形态及查询键生成路由签名。整数、UUID 和部分长标识符归一化；查询参数值不进入签名。没有有效 URL 时归入缺失 URL 层；没有 URL 字段时退化为总体层。路由签名是廉价的分组代理，并不等价于真实 DOM 模板。

S3：对每个已观察分层 s 及必填字段 f 计算样本数 `n_s`、空值数 `z_s,f` 和比例 `q_s,f=z_s,f/n_s`。当前阈值为 `τ=0.2`。任意 `q_s,f>τ` 产生高严重度问题，参与最终硬失败判断，即使全局比例满足门限仍返回 FAIL。

S4：生成覆盖证书。证书含 `scope=observed_records`、每层统计、必需字段对数、失败字段对数和 `complete`。`complete` 仅表示输入记录集合满足分层空值门限；它不证明未访问页面、漏掉的列表项、未采样模板或整站数据全部覆盖。

S5：针对失败字段对生成定向补证指令。指令包含路由签名、失败字段、页面作用域、实际失败记录的 URL、样本及字符上限。采用贪心方式选取能覆盖较多失败字段的失败 URL，最多两个 URL；每份报告最多八个请求，单请求最多三份样本、最多 4,000 字符。正文不写入请求，抓取目标 URL 保留查询值以保持可执行性。

S6：服务端把决定及统计转成受总字节限制的模型回执。超过 16,000 UTF-8 字节时优先省略成功分层详情，然后省略其他详情；保留 PASS/FAIL、已计算记录数及失败字段对总数，声明省略。计算门禁发生在详情省略之前，展示裁剪不会把失败变为成功。实际补取 URL 在请求保留时不做字符串截断。

S7：在自动 `crawl_draft_execute` 流程中，sample 通过后进入 full；只有 full 的 PASS 且已评估记录数覆盖本次输出记录数时才提交记忆。分层失败与既有高严重度问题一样阻断。服务向智能体返回受限重分析指引，智能体经选择器验证后创建新草稿执行。

## 3. 数据结构与程序对应

| 数据/控制 | 实现 |
|---|---|
| 路由签名、分层统计、失败记录代表 URL | `packages/validator/coverage.py` |
| CoverageCertificate / EvidenceRequest / ValidationReport | `packages/crawl_core/models.py`；`schemas/validation_report.schema.json` |
| 分层问题纳入硬失败 | `packages/validator/report.py` |
| prefix/boundary_spread 可选取样 | `packages/compiler/playwright.py`；HTTP/Playwright 执行器 |
| 自动草稿 QA、受限回执、full 提交门禁 | `services/easyspider_mcp/server.py` |
| 定向重分析任务说明 | `deerflow/skills/crawl-validation/SKILL.md`；`deerflow/agents/qa-repair/SYSTEM.md` |

执行清单已有 `task_hash`，草稿已有持久 ID 与终态缓存。它们尚未与补证预算、补取结果及受影响分层复验组成统一证明链，不能把“已有 hash”表述为“已完成版本绑定复验”。

简化请求例：

```json
{
  "stratum": "example.com/special/{n}.html",
  "fields": ["content"],
  "representative_urls": ["https://example.com/special/1008.html"],
  "page_scope": "detail",
  "max_samples": 1,
  "max_chars": 1200,
  "reason": "只补充该失败字段及路由的结构证据"
}
```

例中字符和样本预算为生成的约束声明；目前没有独立的服务端补取接口消费该预算。16,000 字节 QA 回执上限则是已经执行的约束，两者不能混写。

## 4. 可复现实验与目前支持的效果

`scripts/benchmark_verification_coverage.py` 复现全局误放行及取样盲区。`tests/e2e/test_coverage_gate.py` 使用真实本地 HTTP 服务器、原生 HTTP 执行器、编译清单、草稿仓库和 SQLite 记忆库，验证完整调用链。

| 错误规则 `.content` | 旧全局门限 | 新分层门禁 | 记忆提交 |
|---|---|---|---|
| 前五条样本 | PASS | PASS，仅见普通路由 | 未完成 full，不提交 |
| 前缀样本后全量十条 | PASS | FAIL | 阻断 |
| 边界分散五条样本 | PASS | FAIL | 阻断，无需进入 full |
| 修复 `.content, .alternate` 后全量 | PASS | PASS | 自动提交 |

本地尾部变体例中，边界分散错误任务用了 1 次列表和 5 次详情请求；前缀错误任务用了 2 次列表和 15 次详情请求。该请求差异由本例位置和 sample 早停产生，不是普遍加速保证，也不是核心专利性证据。

已经支持的效果：对于观察到的不同路由中的整字段失效，减少原全局均值门限的误放行；生成的补证 URL 来自实际失败记录；自动草稿可以阻断错误规则写入记忆。尚未支持公网泛化、模型修复成功率提高、token 降幅或非显而易见性。

## 5. 实施边界

每层目前独立检查的是必填空值率，语义和重复率仍主要为全局检查。20% 阈值允许一定层内缺失，并非“每条必填数据零缺失”。同一路由中的不同 DOM 模板可能合并，不同路由中的同模板可能拆分。URL 字段选错、原页面真实没有该字段以及缺失 URL 会影响证据质量。

边界分散取样只从第一页候选位置取样，预算为一条时仍选择第一条；它不按 DOM 模板分层，也不保证观察全部模板。即使样本 PASS，完整任务仍需要 final QA。

服务端验证最多读取 1,000 条结果。自动草稿识别 `validation_complete=false` 后不提交记忆；高级接口同样显式返回验证范围标记。报告中的 PASS 此时仍只指已评估部分。公开的手工 `memory_commit_validated` 拒绝 FAIL 及与失败证书矛盾的 PASS，但为兼容旧调用仍接受没有证书的 PASS，且未强制绑定执行 ID/样本阶段。因此本轮交底的强制提交门禁限定于自动草稿路径。

报告最多产生八个补证请求；超过该数量的失败仍计入 FAIL，没有自动分批补证调度。两份代表页未覆盖的字段缺口也没有自动登记为待补证状态。

## 6. 权利要求候选边界（供继续检索）

可讨论的方法骨架：获取异质网页采集记录及必填字段集合；归一化记录的网页 URL 形成路由结构分层；对各已观察分层与必填字段独立计算空值比例并形成覆盖证书；在任一字段对超过阈值时，阻断采集规则的通过判定；依据对应失败记录选择代表页面，输出含字段、页面作用域与证据预算的重分析请求；在自动采集工作流中，只有完成最终输出范围验证并通过上述判定后才提交规则记忆。

从属候选包括具体路由归一化、失败 URL 贪心选择、证书的观察范围声明、回执字节限制与保留失败总数、样本阶段早停。LLM、MCP 及具体数据库可作为可选实施环境。

此骨架只是已经实施内容的准确表达。与 [US20090204889A1](https://patents.google.com/patent/US20090204889A1/en) 的失败属性/代表页面回路及 [CN121167008B](https://patents.google.com/patent/CN121167008B/zh) 的精简输入/规则验证优化组合相比，仍可能显而易见；不建议当前仅修改措辞后立即当作强发明提交。

## 7. 下一阶段研发实施例（当前未完成）

研发应补成实际控制链：候选页登记与未观察状态；路由碰撞时由字段缺口驱动结构细分；不可由模型任意扩大的服务端补证范围与累计预算；补证结果、修复版本和受影响分层复验的绑定；修复后对原成功分层做回归，最后以可核验 full 依据提交记忆。

要证明该组合的技术效果，须在相同补证字节/请求预算下对比现有代表页反馈方案。若只能证明“多加一些检查自然更严格”，仍不足以支撑强创造性；若能在覆盖相同失败的条件下减少无关补证、降低修复回归并控制重复取数，才有继续主张具体耦合机制的依据。
