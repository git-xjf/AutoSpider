# AutoSpider 记忆改进：落地与验证方案

日期：2026-11-15。状态：**研究与工程方案，尚未实现或接入生产**。论文、代码证据与候选效果要分别记录。本文件承接 [结论](README.md) 和 [论文卡片](PAPERS.md)。

## 1. 明确研究问题

主问题：

> 在网页结构与任务条件可能改变、网络又存在临时故障的情况下，如何让采集工作流记忆利用执行反馈决定复用、局部复验或重新分析，在有限网页请求和模型预算下减少错误复用与重复试错？

拆成三个可验证子问题：

| 子问题 | 当前断点 | 需要的证据 |
| --- | --- | --- |
| RQ1：失败如何更新正确的记忆范围 | QA 分数被写入 success_rate；失败日志不影响排序 | 关联具体版本的结果流能降低重复坏规则使用，同时不误伤暂时故障 |
| RQ2：非空选择器是否仍满足任务 | QA 无一般正文来源判定；相同结构不能证明相同归属 | 在独立标注的错区/换栏目案例上，错误接受减少，拒用和核验成本完整报告 |
| RQ3：历史修复是否能减少新一轮模型分析 | 过程经验散在聊天与日志中 | 在新任务/新变化族上，以相同可见信息减少模型用量且不增加错误迁移 |

初期不把“知识图谱效果好”作为待证命题。先证明这些问题和信息需求，再看关系表示是否有额外收益。

## 2. 阶段一：补失败反馈，不先加模型调用

### 2.1 数据模型草案

以下均为建议新增概念，不是已有 MCP 工具或已经存在的数据库表。

```text
workflow_version
  workflow_id, version, source_task_id, field_contract, applicability_scope
  qa_score, last_verified_at, status

memory_observation
  event_id, workflow_id/version, draft_id, execution_id, phase
  field, route_scope, observation_time, outcome, failure_code
  validation_scope, evidence_ref, content_hash, parent_event_id

repair_episode
  task_signature, preconditions, failure_observation_ids
  minimal_patch, validation_observation_ids, disposition
```

第一版可以用 SQLite 表和 JSON；不预先依赖 Neo4j、向量服务或新增 MCP Server。schema 迁移要版本化、可回滚并备份；先以临时库和影子写入验证，不直接迁移用户现有库。

### 2.2 确定性规则

1. 将一次 QA score 与跨执行的经验可靠性分开。旧 `success_rate` 历史值按旧 QA 评分解释，不能追认为真实成功/失败比例。
2. 由服务读取真实终态回执，给事件绑定 workflow/version/execution/范围。重复轮询、重放同草稿结果与多角色转述要按同一事件去重。
3. 只将已归因的选择器/质量失败影响对应规则；临时 HTTP 503、DNS、策略阻断、未知内部错误单独记录，不能一律减选择器分数。
4. 成功样本、完整全量验证和只验证前缀是不同证据等级。失败未解决不能因另一个样本 PASS 就全局抹去。
5. 现有路径/字段/API 参数兼容门禁先执行，相关性、时间或经验分数只用于合格候选之间的排序。
6. 对确认异常的适用范围标记待复验；取得新的对应证据后恢复。不要按一次异常永久停用整个站点。
7. 证据不足保持未知；访问策略仍由现有代码控制。

可以比较 Beta 平滑成功比例、最近窗口和错误码状态机，但它们都是候选常规基线。未进行校准前不要把数值称为真实概率，更不要把访问频率等同于可靠性。

### 2.3 建议接入点

| 位置 | 预期改动 |
| --- | --- |
| `packages/site_memory/repository.py` | 版本化 schema、执行事件、去重、可靠性计算、范围状态查询 |
| `services/easyspider_mcp/server.py` | 在草稿/复用真实终态处统一记结果，不依赖模型主动调用日志工具 |
| `packages/crawl_core/reuse.py` | 保留硬兼容检查，接收明确的待复验决定，不放宽现有 API 参数限制 |
| `tests/unit/test_memory.py` 及新测试 | 更新、状态转移、归因、幂等、迁移回滚、时间顺序 |
| 本地 HTTP E2E | 规则漂移、临时故障、恢复、重新验证后的工作流复用 |

不要只在 `_finish_draft_result()` 写成功与失败：复用路径、样本路径、超时续行和高级执行入口都应明确各自是否产生一次可计数结果。中间状态不重复计数，不能为了方便把采集前阻断记为字段错误。

## 3. 阶段二：增加有界经验检索

### 3.1 记忆分层

| 层 | 内容 | 使用方式 |
| --- | --- | --- |
| 短时观测 | 当前探针、字段计数、错误、执行阶段 | 运行内使用；保留有界原始证据引用 |
| 过程经验 | 失败前提、已验证最小改动、结果与适用条件 | 按任务条件检索少量案例 |
| 已验证程序 | 可以被执行器运行的工作流版本 | 仍经过兼容检查与代码 QA |

借鉴 P01/P02 的管理思想与 P03 的任务—状态—计划单元；不要直接照搬金融记忆的天数参数，也不让生成的反思自动升级成已验证程序。

初始检索条件使用字段集合、执行模式、页面类型、错误码、兼容路由、观察到的来源条件；文本/嵌入只作为排序补充。对外仍返回小摘要与 evidence ID；可先试至多 3 条经验和一个明确的总字符预算，参数必须计入实验与消融，不宣称这些数值已最优。

### 3.2 多智能体职责

- `web-analyst` 提供观察结果，不决定事实最终入库。
- `qa-repair` 提出最小修改及证据指向，不把语言判断当执行 PASS。
- `crawler-lead` 编排；由服务根据确定性合同提交可执行记忆。
- 复制同一条网页/工具结果时保留原 event ID，不能通过多数角色赞同提高证据独立性。

先复用既有 MCP 和角色权限。若增加工具或参数，再同步源模板、实际配置、用户安装副本、Skill 白名单和恢复回执识别；不能只改提示词。

## 4. 阶段三：任务绑定与来源证据

当前难点是旧选择器仍返回正常非空字符串，但选错了对象。候选机制至少要区分：

```text
用户目标实体/栏目/文档
    ↔ 字段要求
    ↔ 当前页候选区域或响应字段
    ↔ 被验证的规则版本与观测
```

潜在证据包括真实 canonical/实体标识、列表与详情关联、公开响应字段、结构化文章元数据、可验证的提取边界。它们都要单独检验可靠性；如果全部来自同一个会共同漂移的模板，不能假定为相互独立。

保留已有研究的限制：差分回放能验证声明源到输出的依赖，不证明上游语义真值；完整回放还需要网页与资源闭包；同文本、重复渲染和分支变化可能使证据失效。不得把历史 v3 研究原型当已经解决了自动来源发现。[已有结果](../../patent/memory-v3-2026-10-20/RESULTS.md)。

图表示若采用，只组织节点、边、版本与证据引用；“因果”边只有可执行干预或其他足够证据时才能赋予相应含义。普通事件先后关系不能写成已证明的因果。

## 5. 公平基线

所有方法共享相同历史、候选规则、网页响应、字段要求、可见特征、QA 合同和预算。真值标签只供评分。需要分别比较机制组件，不能把整个新增系统只对照裸缓存。

| 基线 | 定义 | 用途 |
| --- | --- | --- |
| B0 当前生产 | 未加入本方案的现有 compact + workflow reuse | 衡量实际新增收益 |
| B1 常规更新 | 原有硬门禁 + 按错误码状态机/失败计数 + TTL 复验 | 防止把普通失败治理包装为新算法 |
| B2 条件排序 | 相同可见信息的字段/模式/路由过滤 + 时效/可靠性排序 | 区分任务条件与复杂表示的收益 |
| B3 强缓存 | 逐 URL 收据与完整投影缓存，重用此前研究中较强策略 | 对照重复核验与适用性共享 |
| B4 普通经验检索 | BM25 或向量 top-k + 同样硬条件/上下文预算 | 判断新增经验组织是否必要 |
| B5 同信息关系查询 | 同节点、同边/属性、同索引预算，以 SQLite/平表连接查询 | 判断图实现是否带来超出表示的收益 |
| 候选 | 有具体差异的更新/选证据/经验检索机制 | 未实现前不填写效果数字 |

如果候选与 B5 逐项相同，应记录等价，不能以“内部用了图”宣称优于常规方法。若只赢 B0、但输/平 B1，应把结论定位为常规工程补全。

## 6. 数据与测试序列

### 6.1 受控回归

先覆盖下列变化族，每族必须包含恢复或对照，不把构造例当真实站点事故率：

1. 正常规则反复执行，确保不重复分析或重复记账。
2. 一次 503 后恢复，保留规则可用性。
3. DOM 容器变化导致空匹配，修复后验证恢复。
4. 旧选择器落入非空推荐区，来源错误但常规字段指标正常。
5. 同路径查询改变栏目，同时页面槽位或属性共同漂移。
6. 新字段或 API 固定参数变化，继续遵守现有拒用规则。
7. 两角色转述同一失败，以及重复回执，验证不能重复计数。
8. 修复新变体却损坏旧成功变体，检查回退与适用范围。
9. 样本 PASS、后续变体 FAIL，或实际输出超过完整验证范围。
10. 可见观测一致但实际来源不同，验证证据不足时的拒用代价。

现有 [2026-11-15 隔离诊断](PROJECT_MEMORY_RECHECK.json) 可作为问题回归起点，不得把同一开发集反复调参后的改善当独立确认效果。

### 6.2 真实新闻站序列

继续使用项目已有且允许采集的公开新闻站。规划至少三个站点、各自多个自然时间点或明确版本的快照；此处是采集设计，不代表现有数据已经满足。

每份资料保存原始 URL、时间、状态、内容 hash 和必要响应；涉及动态来源验证才保存所需脱敏网络/资源证据。不补造历史版本，不把人工修改后的页面当自然漂移。

标注栏目、实体、标题、正文所属区域、字段缺失与歧义。优先由独立标注者核对；不能仅标“非空”，也不能让策略读到正确选择器或答案。按站点/时间/变化族划分开发和冻结确认集，防止相邻快照泄漏。

来源可公开并不表示所有页面允许访问；仍保留项目访问策略。无法取得足够证据时记录缺失，不替换成未说明的合成数据。

## 7. 指标与成本账本

至少报告：

| 指标 | 口径 |
| --- | --- |
| 错误接受 | 接受但不满足独立任务/来源真值的次数；同时报告占全部决策比例 |
| 接受中的错误率 | 错误接受 / 全部接受；全部拒绝时未定义，不能写成自动达到 100% 精确 |
| 正确复用覆盖 | 正确接受 / 真实可以正确复用的任务数 |
| 误拒用与未知 | 可正确复用却拒用，以及证据不足的任务分别报告 |
| 坏规则重复采纳 | 确认失败后又在同失效范围被采纳的次数 |
| 恢复能力 | 临时故障消失后恢复有效规则所需次数/时间 |
| 修复回退 | 新修复导致原成功范围失败的次数 |
| 实际完成 | 满足原字段、页数/条数与验证范围的任务比例 |
| 模型费用 | 全部角色与后台调用的 input/cache/output、调用数、实际提供方费用 |
| 非模型成本 | HTTP 请求、浏览器启动/加载、解析、嵌入、建索引、存储和墙钟时间 |

入库、摘要、索引、重检和失败尝试全部计费。区分冷启动、温启动与多任务摊销；不能只报告检索阶段更短。API tokens 不直接等于人民币成本，摘要字符变少也不等于 tokens 等比例减少。

同站点页面、同一漂移事件的多轮重复不是独立样本。先报告配对逐例结果和完整分母，后续统计按站点/轨迹分组，不对几十个相关页面虚构独立显著性。

## 8. 继续与停止门槛

### 工程采用门槛

- 对比 B0，已确认坏规则重复使用减少，临时故障不导致永久误封。
- 原兼容任务与访问策略无新增回归。
- 事件去重、版本与验证范围可审计，来源未知不自动升级为已验证。
- 真实模型试验记录总成本；增加的更新/检索调用不能掩盖净开销。

### 新研究机制门槛

- 在同信息、同预算条件下，相对 B1—B5 的适用强基线有可复现差异与收益。
- 在冻结新变化族中成立，而非只修复人工特例或开发集。
- 若质量与成本有取舍，报告曲线与完整分母，不称全面优越。
- 图与非图若等价，停止将图表示作为主要贡献，保留有用工程改动。

“方向有价值”与“新增机制已经有效”是不同阶段。本轮仅完成文献核验与当前缺口复跑，不能提前写实验胜出、专利创造性或可直接提交的权利要求。
